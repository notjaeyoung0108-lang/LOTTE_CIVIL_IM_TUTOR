# LOTTE CIVIL IM TUTOR

**롯데건설 토목 IM 학습튜터** — 공사·공무 기본 개념을 배우고, 토목 현장 영향을 이해하고, 복합 문제 해결안을 직접 말하는 모바일 우선 학습 웹앱입니다.

개인 면접 준비용 비공식 도구입니다. 회사 공식 자료·평가 기준을 표방하지 않습니다. 예제 프로젝트는 모두 교육용 가상 상황입니다.

**바로 사용하기: [LOTTE CIVIL IM TUTOR 웹앱](https://notjaeyoung0108-lang.github.io/LOTTE_CIVIL_IM_TUTOR/)**

## 안재영과 함께하는 현장 시뮬레이션

주인공 **안재영**이 신입에서 5년차로 성장하며 10개 장의 현장 사건을 연결합니다. 판단 수준은 현장 5년차의 사고 프레임을 목표로 하고, 설명은 신입이 “왜?”를 따라갈 수 있도록 구성했습니다. 실제 5년의 경력이나 작업 승인 권한을 교재 수료로 대체하지 않습니다.

각 장은 현장 대화 → 화면 정지 → 행동의 이유 → 용어·기술 해설 → 시간축 → 조건 변경 → 판단 문제로 이어집니다. 기존 기술 설명·계산 연습·카드·Case 연결은 유지합니다. 장면의 시간·수량은 교육용 가정이며 판정 기준은 현장 적용 문서에서 확인합니다.

## 실행

폴더 전체를 유지한 채 **index.html을 브라우저에서 직접 엽니다.** 서버·로그인·설치·빌드·API 키가 필요 없습니다. data/*.js를 일반 script로 읽기 때문에 file://에서도 카드·교재·Case가 동작합니다. 외부 CDN·웹폰트를 사용하지 않으며 참고문헌 링크를 누를 때만 외부 사이트로 이동합니다.

원하면 이 폴더에서 아래 명령으로 정적 HTTP 테스트를 할 수 있습니다. 앱 실행에 서버가 필수인 것은 아닙니다.

```sh
python3 -m http.server 8000
```

브라우저에서 http://localhost:8000 을 엽니다. 파일 직접 열기와 HTTP 접속은 별도의 저장 공간을 사용합니다.

직접 링크: `#book/4`, `#s1/s1-001`, `#s2/s2-037`, `#s3/case-001`. 카드의 교재 링크와 교재의 단계별 학습 링크가 연결됩니다. 직접 선택은 현재 필터와 무관하게 요청한 카드를 열며, 평가 후에는 필터가 적용된 큐로 돌아갑니다.

업무 필터는 1~3단계에 공통 적용되고 저장됩니다. 주요 category 또는 tags가 일치하면 포함합니다. 실전에는 난이도·분야 필터도 교차 적용합니다. 일치하는 자료가 없으면 필터 초기화 안내를 보여줍니다. 탭 badge는 필터에 해당하는 **복습 기한이 된 항목만** 셉니다.

## 학습과 반복 알고리즘

- 몰랐어요: 평가 시점 + 60,000ms
- 헷갈려요: 평가 시점 + 1,200,000ms
- 설명할 수 있어요: 평가 시점 + 86,400,000ms

간격은 매번 고정입니다. 평가 횟수에 따라 배수로 늘리지 않습니다. 평가 후 다음 카드를 고를 때 만기 카드를 가장 오래 기다린 순서로 먼저 고릅니다. 만기 카드가 없으면 아직 평가하지 않은 카드를 데이터 순서대로 고릅니다. 없으면 다음 복습 카운트다운을 표시하고 기한이 되면 자동으로 재개합니다. 자유 연습 한 장을 선택할 수도 있습니다.

새로 진입한 학습 탭에서도 만기 카드가 우선입니다. 카드를 읽거나 초안을 작성하는 중에 타이머가 현재 항목을 강제로 바꾸지는 않습니다. 직접 링크로 선택한 항목은 해당 선택을 우선합니다.

기본·도메인의 ‘외운 카드’는 최근 평가가 3인 카드 수입니다. Case 완료는 모범 접근 화면에서 평가 버튼을 누른 시점으로 정의합니다. 단순 열람·초안 입력·Rubric 체크만으로 완료 처리하지 않습니다. Rubric 체크 수는 스스로 확인한 항목 수이고, AI 점수나 합격률이 아닙니다.

PC에서는 `Space`로 앞·뒤 전환, `1`·`2`·`3`으로 뒷면에서 평가합니다. textarea·input·select·편집 영역에서는 학습 단축키가 동작하지 않습니다. 버튼·링크에 초점이 있으면 기본 키보드 동작을 유지합니다.

## 카드 추가

data/stage1.js의 `window.STAGE1` 또는 data/stage2.js의 `window.STAGE2` 배열에 항목을 추가합니다. ID는 기존과 중복하지 않으며, 기존 ID를 바꾸면 그 카드의 저장 기록 연결이 끊깁니다.

```js
{
  id: "s1-083", s: 1,
  domain: "공정관리", category: "공정", tags: ["공무"],
  chapter: 2, g: "새 개념", q: "현장에서 무엇을 확인해야 하는가?",
  a: "**정의 — ...**\n\n- **왜 필요한가:** ...\n- **누가 사용하는가:** ...\n- **연결 자료:** ...\n- **현장 활용·문제 영향:** ..."
}
```

category는 `공사 / 공무 / 공정 / 원가 / 품질·안전 / 현장리스크` 중 하나입니다. tags는 추가 필터 연계에 사용합니다. chapter는 1~10입니다. 2단계 답변은 현상·개념, 원인, 현장 영향, 관리방법, 관리 연결을 포함하세요. 앞뒤 문구를 바꾼 중복 카드보다 다른 판단 질문을 작성합니다.

본문은 제목, 문단, 목록, 인용, 단순 표, `**강조**`, 인라인 코드, HTTPS 링크를 지원합니다. 원시 HTML은 실행되지 않습니다. 일반 Markdown 전체 문법을 구현한 파서가 아니므로 지원 문법 안에서 작성합니다.

## Case 추가

data/cases.js의 `window.CASES`에 새 ID를 추가합니다. case-002 이후 사례를 형식 참고로 사용하되 고유한 원인·제약·대안을 작성하세요.

```js
{
  id: "case-033", s: 3,
  difficulty: "중급", field: "지반", domain: "지하수",
  category: "현장리스크", chapter: 4, tags: ["공정", "원가"],
  title: "새로운 상황", background: "프로젝트·공정률·잔여기간·계약조건...",
  issues: ["동시 조건 1", "동시 조건 2", "동시 조건 3", "동시 조건 4"],
  question: "당신이 현장 책임자라면 어떻게 해결하겠는가?",
  hints: ["위험 확인", "원인과 공정 영향", "대안 비교"],
  framework: [
    // 상황 파악, 우선순위 설정, 원인·영향 분석, 대안 도출,
    // 대안 비교 및 선택, 실행·협의, 모니터링의 7개 {title, body}
  ],
  comparison: [
    // 최소 2개 대안. 제시되지 않은 금액·기간을 임의 확정하지 않습니다.
    {name:"대안 A", time:"공기효과", cost:"추가비용", safety:"안전",
     quality:"품질", civil:"환경·민원", approval:"승인조건"}
  ],
  interviewAnswer: "2~3분 동안 말할 수 있는 지원자 관점의 답변...",
  keyPoints: ["핵심 확인사항..."], pitfalls: ["피할 답변..."]
}
```

field는 `토공 / 지반 / 구조 / 도로 / 교량 / 터널 / 도심지 / 종합`, difficulty는 `기본 / 중급 / 고급`입니다. 동시 조건은 4~7개로 작성합니다. 배경에서 불명확한 금액·계약은 미제시로 밝히거나 교육용 가정임을 명시합니다. 기본 2~4개 대안, 지정 종합 사례는 6개 대안을 비교합니다.

모범 접근은 문제 정의·즉시 조치·원인 영향·대안 설정·비교·결정·협의·사후관리의 내용을 7단계에 담습니다. 면접 답변은 소리 내어 읽고 길이를 확인하세요. 현재 데이터는 약 900~1,140자이며 개인 속도에 따라 달라집니다.

`window.LotteTutor.evaluateCaseAnswer(caseId, userAnswer)`는 미래 확장용 인터페이스입니다. 현재는 `mode: "self-review"`, Rubric, `feedback: null`, `score: null`을 반환할 뿐 외부 전송·채점은 하지 않습니다.

## 저장 구조

키: **lotte_civil_im_tutor.v1**

```js
{
  version: 1,
  cards: {
    "s1-001": { reps: 2, last: 0, due: 0, grade: 3, misses: 1 }
  },
  cases: {
    "case-001": {
      answer: "나의 답변", hints: 2,
      rubric: [true, false, false, false, false, false, false, false],
      completed: false, viewed: 0, lastPracticed: 0
    }
  },
  filters: { category: "전체", difficulty: "전체", field: "전체" },
  log: [{ id: "s1-001", at: 0, grade: 3 }],
  book: { last: 1, read: [1] }
}
```

시간은 Unix epoch 밀리초입니다. 위 0은 구조 예시입니다. 답변은 입력 이벤트마다 동기 저장하고 힌트·체크도 즉시 저장합니다. 완료는 유지되며 최근 평가는 별도로 변합니다. 저장 실패는 숨기지 않고 화면 상단에 안내합니다. 잘못된 저장 구조는 검증 후 기본값으로 처리합니다.

기록 탭의 백업은 전체 JSON을 내려받습니다. 현재 버전에는 백업 불러오기 UI가 없습니다. 초기화는 확인 화면의 ‘모든 기록 삭제’를 눌렀을 때만 전체 학습 상태를 지웁니다.

## 시뮬레이션 조판 검증

교재의 도식·모바일 표시를 수정했다면 `tools/simulation-qa.cjs`를 실행합니다. 기존 브라우저 QA와 같은 외부 Playwright·Chrome 설치를 사용하며, 필요하면 `PLAYWRIGHT_PATH`와 `CHROME_PATH`로 위치를 지정합니다. 결과는 `docs/qa/simulation-results.json`에 기록됩니다.

## 교재 수정

docs/01_*.md~10_*.md를 수정한 뒤 다음 명령을 실행합니다.

```sh
node tools/build-book.js
node tools/validate.js
```

data/book.js도 변경분에 포함해야 합니다. 이 명령은 교재를 수정할 때만 필요하며 사용자가 앱을 실행할 때는 필요하지 않습니다. build-book.js는 자신의 경로를 기준으로 파일을 찾으므로 어느 작업 디렉터리에서 실행해도 됩니다.

## GitHub Pages 배포

1. 새 GitHub 저장소를 만들고 이 폴더의 파일과 data/, docs/, tools/를 루트에 업로드합니다.
2. Settings → Pages → Build and deployment에서 **Deploy from a branch**를 선택합니다.
3. 업로드한 브랜치의 **/(root)**를 선택하여 저장합니다.
4. 배포 완료 후 GitHub가 표시하는 URL을 엽니다.

모든 런타임 경로는 상대경로이고 화면은 hash로 전환되므로 `/저장소이름/` 하위에서도 동작합니다. 별도의 SPA rewrite가 필요 없습니다. 이 저장소는 공개 저장소이며, `main` 브랜치의 루트를 GitHub Pages로 배포합니다. 이후 `main`에 push하면 자동으로 다시 배포됩니다.

## QA

```sh
node --check app.js
node tools/validate.js
```

브라우저 QA는 개발·검증용 Playwright가 있는 경우 실행할 수 있습니다. **앱 실행 의존성이 아닙니다.** 설치 경로는 프로젝트 밖이어도 됩니다.

```sh
PLAYWRIGHT_PATH=/absolute/path/to/node_modules/playwright \
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
node tools/browser-qa.cjs
```

다른 OS에서는 CHROME_PATH에 해당 Chrome 실행 파일 경로를 지정합니다. 테스트는 격리된 브라우저 컨텍스트에서 수행되어 일반 사용자 Chrome 프로필을 사용하지 않습니다. 결과와 이미지가 docs/qa/에 생성됩니다. 상세 결과는 [QA 기록](docs/QA.md)을 참고하세요.

## 참고와 제한

[참고 앱](https://github.com/notjaeyoung0108-lang/SKCT_BIM-5D)의 정적 실행·교재·카드·반복·5탭 철학을 분석하고 새 코드·콘텐츠로 구현했습니다. [분석 문서](docs/REFERENCE_ANALYSIS.md)에 대응 관계를 정리했습니다.

기술·계약 학습 내용은 일반 원칙입니다. 실제 현장에는 해당 설계·시방·계약·현행 규정과 담당 전문가의 판단이 필요합니다. [국가건설기준센터](https://www.kcsc.re.kr/), [FHWA 공정 추정](https://www.fhwa.dot.gov/majorprojects/schedule_estimating/), [FHWA 원가 위험평가](https://www.fhwa.dot.gov/majorprojects/cost_estimating/CSRA.cfm), [FHWA 터널 매뉴얼](https://highways.dot.gov/media/180616)을 참고 방향으로 연결했습니다. 해외 자료를 국내 계약 기준으로 적용하지 않습니다.

Chrome에서 자동화와 화면 검증을 마쳤습니다. 실제 iOS Safari·Android 기기의 키보드·저장 동작은 별도 실기기 검증이 필요합니다. file:// 저장소는 브라우저 정책과 파일 위치에 따라 달라질 수 있어 안정적인 장기 사용에는 고정된 Pages 주소가 편리합니다. 기기 간 동기화·AI 평가·여러 탭 동시 편집 병합은 제공하지 않습니다. 여러 탭 변경은 알림만 제공하므로 한 탭에서 학습하는 것을 권장합니다.
