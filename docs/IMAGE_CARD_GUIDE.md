# 이미지 플래시카드 운영 가이드

기존 정적 웹앱의 데이터 배열에 카드를 누적한다. 학습 범위는 토공·굴착·가시설, 지반·기초·말뚝, 철근콘크리트, 구조, 배수·상하수·관로, 도로·포장, 터널·계측, 측량·도면, 품질·안전, 공무·물량·기성·변경·문서 전반이다.

## 스키마와 복사 템플릿

`data/stage1.js`의 `window.STAGE1` 또는 `data/stage2.js`의 `window.STAGE2` 배열에 추가한다. 단계 3은 상황 해결 Case이므로 이 템플릿을 넣지 않는다. 별도 로더나 빌드는 필요 없다.

```js
{
  id: "s2-206", // 새 ID 예시: 사용 전 저장소 전체에서 중복 확인
  s: 2,
  domain: "구조",
  category: "공사",
  chapter: 9,
  g: "개념명",
  q: "하나의 개념을 묻는 짧은 회상 질문",
  a: `**정의 — 개념의 뜻.**

- **왜 필요한가:** 목적.
- **누가 사용하는가:** 관련 담당자.
- **연결 자료:** 도면·기록·시험 등의 자료.
- **현장 활용·문제 영향:** 확인할 사항과 후속 영향.`,
  answerFormat: "concept",
  tags: ["구조", "도면"],
  status: "draft"
  // 이미지가 실제로 준비되면 아래 두 필드를 함께 추가한다.
  // image: "assets/flashcards/structure/s2-206.png",
  // imageAlt: "이미지의 핵심 관계를 설명하는 짧은 문장"
}
```

| 필드 | 규칙 |
| --- | --- |
| `id`, `s` | 기존 ID 불변. 단계와 ID 접두사를 맞추고 전역 중복 금지 |
| `domain`, `g`, `q`, `a` | 분야·개념·질문·답변. 빈 내용 금지 |
| `category` | 공사 / 공무 / 공정 / 원가 / 품질·안전 / 현장리스크 |
| `chapter` | `docs/curriculum.json`에 있는 관련 교재 번호 |
| `answerFormat` | 새 개념 카드는 `concept`. 기존 카드는 생략 가능 |
| `image` | 선택. `assets/flashcards/<분야>/<card-id>.png` 상대 경로 |
| `imageAlt` | 이미지 연결 시 필수. 핵심 관계를 짧게 설명 |
| `tags` | 문자열 배열. 새 개념 카드에는 하나 이상 |
| `status` | 새 개념 카드에는 `draft`, `review`, `final` 중 하나 |

`answerFormat`은 단계 2의 기존 ‘현상·원인·현장 영향·관리방법·관리 연결’ 답변과 새 5항목 정의형 답변을 구분한다. 기존 카드 검증은 유지한다. `status`는 편집 상태이며 학습 노출을 차단하지 않는다. 검토 전 샘플은 모두 `draft`로 둔다.

## 이미지 저장과 표시

| 폴더 | 용도 |
| --- | --- |
| `common` | 공통 개념 |
| `earthwork` | 토공·굴착·가시설 |
| `geotech` | 지반·기초·말뚝 |
| `structure` | 구조·철근콘크리트 |
| `drawing` | 측량·도면 |
| `quality` | 품질 |
| `safety` | 안전 |
| `contract` | 공무·물량·계약·문서 |

배수·관로, 도로·포장, 터널 등은 필요할 때 `drainage`, `road`, `tunnel` 폴더를 추가한다. 폴더명은 영문 소문자, 파일명은 카드 ID와 일치시킨다. 이미지 없이 먼저 등록할 때는 `image`와 `imageAlt`를 생략한다. 존재하지 않는 예정 경로를 넣지 않는다. 나중에 이미지를 추가해도 ID를 바꾸지 않아 학습 기록이 유지된다.

`app.js`의 `flashImage()`가 질문 아래와 답변 위에 같은 이미지를 표시한다. alt의 런타임 대체 순서는 `imageAlt → g → q`다. 경로와 alt를 HTML 이스케이프한다. 로드 오류는 캡처 이벤트로 처리해 깨진 이미지를 숨기고 안내를 표시한다. `.flash-image`는 가용 폭 100%, 이미지 최대 폭 720px, 높이 자동으로 모바일 비율을 유지한다.

## 카드 작성과 검토

한 카드에는 하나의 개념과 직접 연결된 질문만 담는다. 정의는 2~4문장 이내를 권장하며, 나머지는 짧은 항목으로 쓴다. 기존 `g`, `q`와 유사한 회상 목표가 있는지 검색하고 중복이면 기존 ID를 보완한다. 분야 이름과 태그는 기존 표기를 재사용한다.

실무 판단의 출발점을 제공하되 현장 승인이나 기술 검토를 대체하지 않는다. 법규·수치·허용오차는 일반화하지 않고 필요하면 ‘프로젝트 기준 확인’을 명시한다. 여굴 입문 정의와 기존 터널 여굴의 공정·원가 영향처럼 회상 목표가 다른 경우에만 별도 카드를 둔다.

개념도 → 평면/단면 스케치 → 공정 흐름도 → 비교도 → 단순 인포그래픽 순으로 선택한다. 밝은 배경, 4:3 또는 1:1 비율, 최소 라벨, 단순 색상을 사용한다. 회사 로고와 민감 정보는 제외한다. 생성 후 형상·라벨·지시선이 답변과 일치하는지 직접 확인한다.

```text
교육용 토목 플래시카드용 이미지.
주제: [용어/개념명]
스타일: 깔끔한 기술 인포그래픽 또는 단순 개념도
구성: [핵심 요소 3~5개]
텍스트: 최소한의 한글 라벨만 사용
배경: 흰색
목적: 초급~중급 학습자가 개념을 직관적으로 이해하도록
금지: 과도한 장식, 복잡한 배경, 불필요한 인물, 실제 회사 로고
```

이번 PNG 3장은 내장 이미지 도구로 생성했다. 실제 사용한 프롬프트는 [생성 기록](IMAGE_CARD_PROMPTS.md)에 보관한다.

## 반영 절차

1. 기존 카드와 중복 여부를 확인하고 내용이 완성된 `draft` 카드를 등록한다.
2. 준비된 이미지만 저장하고 경로·alt를 함께 추가한다.
3. 아래 검사와 브라우저 확인 후 분야별 5~15장 단위로 커밋한다.
4. 내용·도식 검토를 거쳐 `review → final`로 변경한다. 이미지 추가·교체 시 ID는 유지한다.
5. 지반·토공에서 구조·품질·공무 등으로 확대한다. 전체 분야가 완성될 때까지 기다리지 않는다.

```bash
node tools/build-book.js
node tools/validate.js
node --check app.js
# Playwright 외부 설치를 사용할 수도 있다.
PLAYWRIGHT_PATH=/path/to/playwright node tools/image-card-qa.cjs
```

검증 도구는 ID·질문 중복, 답변 항목, 메타데이터, 이미지 경로·파일명·PNG 헤더를 검사한다. 브라우저에서는 320/390/1280px 폭, 앞·뒤 이미지, 이미지 없는 카드, 로드 실패, alt 대체, 자기평가 기록 유지를 확인한다.
