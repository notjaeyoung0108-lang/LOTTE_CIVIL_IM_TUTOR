## 전체 구조

참고 저장소는 index.html, app.js, style.css, README.md, data/{vol1,vol2,vol3,book}.js, docs/ 원문 3개, tools/build-book.js, assets/font/BMJUA.woff2로 구성되어 있다. 프레임워크·패키지 빌드·런타임 API 서버가 없다. Node는 교재 직렬화 도구에만 쓰인다.

## 파일과 데이터 흐름

- README.md: 실행·탭·3단계·고정 반복 간격·즉시 큐 재계산·권별 필터·교재 빌드·데이터 추가·내보내기를 설명한다.
- index.html: 헤더·main·하단 5탭의 단일 껍데기. 자료는 fetch나 모듈이 아닌 일반 script로 싣는다.
- app.js: hash 라우팅, 단일 localStorage 상태, Markdown 조판, 반복 스케줄, 앞뒤 카드, 교재 목차/장 이동, KPI·진행률, 설정·내보내기·초기화를 담당한다.
- style.css: 720px 읽기 폭, 모바일 우선 카드·얇은 경계·둥근 모서리, 고정 하단 탭, safe-area, 가로 필터, 반응형 색상, 표 내부 스크롤을 제공한다. 제목용 자체 폰트와 카드 본문 고딕을 분리한다.
- data/: 세 권의 파일이 window.DECK에 카드를 추가한다. 각 카드의 s가 학습 단계, v가 권 구분이다. window.BOOK은 원문 Markdown 문자열을 제공한다.
- docs/: 용어를 정의와 문제 상황 두 축으로 정리한다. 제목·목록·표·코드 흐름도·인용을 사용하며 원문을 앱에서 읽게 한다.
- tools/build-book.js: 원문 파일의 제목과 내용을 읽어 data/book.js로 직렬화한다. 실행 중에는 원문을 fetch하지 않는다.

## 유지한 학습 철학

읽기 → 카드에서 회상 → 어려운 개념의 교재 재방문 → 자기평가 → 간격반복을 유지했다. 단계 간 이동에 로그인이나 서버가 필요 없다. 복습 기한은 넘길 때 다시 판단한다. 복습이 없으면 새 카드를, 둘 다 없으면 다음 기한 대기를 표시한다.

원래 1분·20분·1일의 고정 간격을 유지했다. 장기 적응형 알고리즘으로 변경하지 않았다. 참고 앱의 카드 뒷면에 있는 세 평가 버튼을 현장 설명 가능성 중심 문구로 바꿨다.

## 이번 프로젝트의 재설계

- 3개 Vol이 아니라 공사·공무·공정·원가·품질안전·현장리스크 필터로 전환했다.
- 일반카드와 Case를 분리했다. Case는 상황·복수 조건·초안·단계별 힌트·7단계 접근·대안표·구두 답변·Rubric을 가진다.
- 난이도·분야 필터와 전체 Case 직접 선택을 추가했다. 001 고급 종합 예제 뒤에는 기본→중급→고급으로 배치했다.
- 교재는 새 토목 현장관리 원문 10장으로 작성하고 카드와 직접 연결했다.
- 진행률에서 기본·도메인은 최근 ‘설명할 수 있어요’, Case는 모범 접근 확인 후 자기평가 완료로 정의해 화면에 설명했다.
- 참고 앱의 localStorage 예외 무시 대신 실패를 표시한다. 깨진 상태는 검증·정규화하며 입력은 HTML로 실행하지 않는다.
- 입력 요소에서 단축키를 끄고, 키 반복·조합 입력을 제외한다.
- 브랜드 로고·폰트·기존 코드·기존 학습 콘텐츠를 복제하지 않았다. 시스템 글꼴, 자체 CSS, 간단한 자체 SVG 단면 장식, 새로운 일반 JS 구조를 사용했다.

## 의도적인 범위

외부 프레임워크, CDN, LLM 채점, 서버 저장, 실제 발주처 계약 판정은 없다. 장식보다 학습을 우선하고, 기업 홍보와 게임 요소를 넣지 않았다. 표는 모든 비교축을 보존하면서 모바일에서 해당 영역만 가로로 스크롤한다.
