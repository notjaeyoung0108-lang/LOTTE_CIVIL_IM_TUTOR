# A01-3. Activity는 어떻게 정의하는가

※ 아래 물량, 생산성, 인원, 비용 및 일정은 교육용 가정이다.

이 장의 수치 예시는 Activity 후보의 건수와 상태 종류를 설명하기 위한 것이다. 단위는 `건·종·%`이며, 범위는 B2 교육구간의 WBS 말단 후보 1건이다. 작업일·달력일·작업시간대·Crew(하나의 작업조)·물량·생산성은 산정하지 않는다. 따라서 생산성 분모와 일정 계산은 해당하지 않으며, 비용은 전 항목을 제외한다. 날짜도 사용하지 않으므로 달력일을 작업일로 환산하지 않는다.

## Level 1. Activity와 WBS의 차이

**WBS(Work Breakdown Structure, 작업분류체계)**는 공사 범위를 위치·공종·결과물에 따라 나눈 체계다. **Activity(공정 작업)**는 그 WBS 범위 안에서 시간이 흐르며 상태가 바뀌고, 시작·진행·완료를 따로 판정할 수 있는 작업 단위다.

예를 들어 WBS가 ‘B2 교육구간 α 바닥부’라는 관리 범위를 나타낸다면, Activity는 적용 도면에 해당 공종이 존재한다는 전제에서 ‘B2 교육구간 α 바닥부 철근 조립’처럼 **위치+대상+행동**이 드러나야 한다. WBS 말단 하나가 반드시 Activity 하나가 되는 것은 아니다.

## 실제 업무 장면: 한 줄짜리 작업을 그대로 공정표에 넣어도 되는가

주간 상세공정 확정 전에 계획담당자는 A01-2에서 만든 B2 WBS 말단을 받았다. 최초 명칭은 ‘B2 교육구간 α 바닥부 구조체 준비 및 검측’이었다. 그러나 이 명칭만으로는 철근 조립, 매립물 설치, 거푸집 조립, 프로젝트에서 요구하는 검사 상태 중 무엇이 시작됐고 무엇이 끝났는지 구분할 수 없었다.

최초 제공 정보와 질문 뒤 확보한 답은 섞어 기록하지 않는다.

| 구분 | 확보한 내용 | 아직 판단할 수 없는 내용 |
|---|---|---|
| 최초 제공 정보 | WBS 코드, 교육구간 α의 위치 경계, 통합 작업명, 관련 도면번호 목록 | 현장 적용 개정, 포함 공종, 검사 요청 문서명, 완료 승인 역할 |
| 질문 뒤 확보한 답 | 공사담당자는 공종별 작업조와 인계 시점이 다르다고 답했다. 조달담당자는 현장 반입과 작업면 사용 가능이 같은 상태가 아니라고 답했다. | 품질 확인을 별도 Activity로 둘지, 시공 Activity의 완료조건에 포함할지는 프로젝트 절차 확인 전까지 미결이다. |

따라서 계획담당자는 통합 명칭을 바로 확정하지 않는다. 먼저 물리적 시공 상태와 품질 확인 상태를 나누어 보고, 각각 독립적으로 갱신해야 일정 영향이 보이는지를 판단한다.

## Input: 어느 자료의 어느 칸을 읽는가

| 자료 | 읽을 칸·개정·기간·범위 | 읽는 이유와 결정 |
|---|---|---|
| WBS 사전 | 말단 코드, 위치 경계, 포함·제외 범위, 적용 개정 | Activity가 다른 구간과 중복되거나 빠지지 않도록 범위를 고정한다. |
| 도면목록과 적용 도면 | 도면번호, 개정번호, 발행 목적, 사용 상태, 적용 구간, 배포 이력 | 최신 번호만 보는 것이 아니라 해당 구간에 실제 사용 가능한 개정인지 확인한다. 구조 상세 자체를 계획담당자가 새로 정하지 않는다. |
| 시공계획 자료 | 작업순서, 작업면 조건, 사용 장비·자재, 공종 간 인계 지점 | 한 Activity 안에 서로 다른 작업조와 인계 상태가 뭉쳤는지 찾는다. 시공방법 승인은 프로젝트 절차를 따른다. |
| 물량 산출 범위 | 위치코드, 산출 대상, 포함·공제 조건, 적용 도면 개정 | 이후 진도와 기간 산정이 같은 분모를 사용하도록 Activity 범위를 맞춘다. 이 장에서는 물량값을 산정하지 않는다. |
| 자재·장비 자료 | 품목 식별, 적용 위치, 반입 상태, 검사·사용 가능 상태, 필요 시점 | ‘발주’, ‘반입’, ‘작업면 배치’, ‘사용 가능’을 구분해 시작조건을 쓴다. |
| 품질계획·검사 절차 | 검사 대상, 확인 시점, 요청·기록 양식, 다음 단계 진행 조건, 담당 역할 | 검측 요청과 합격·종결을 혼동하지 않기 위해 읽는다. 문서명, 검사빈도와 승인 권한은 프로젝트 문서에서 확인한다. |
| 안전계획·작업 전 통제자료 | 적용 작업, 위험요인, 작업 전 조치, 허가나 확인이 필요한 경우 그 절차 | 안전조치를 일정에서 삭제하지 않고 착수 가능 조건에 반영한다. 법정 기준이나 회사 고유 절차를 임의로 만들지 않는다. |
| 최신 공정표와 작업일보 | 공정표의 상태일·갱신본·선후 작업, 작업일보의 해당 작업면 기록 시작부터 현재 상태일까지 | 정의한 Activity가 기존 실적 기록과 같은 위치·완료기준으로 비교되는지 시험한다. **상태일**은 실제 진도를 고정해 보는 기준시점이다. |

## 담당자의 실제 업무순서와 이유

1. **기준 범위를 잠근다.** WBS 코드, 위치 경계와 적용 도면의 식별정보를 먼저 적는다. 이를 뒤로 미루면 서로 다른 개정이나 구간을 같은 Activity로 비교하게 된다.
2. **결과물을 한 문장으로 쓴다.** ‘준비’, ‘처리’, ‘구조물 작업’ 대신 위치·대상·행동을 쓴다. 예시는 ‘B2 교육구간 α 바닥부 철근 조립 및 자체점검’이다.
3. **포함·제외를 적는다.** 적용 도면 범위의 철근 조립과 자체점검은 포함하되, 자재 구매·현장 반입, 다른 공종의 매립물 설치, 프로젝트 절차상 검사·승인은 제외 후보로 기록한다. 실제 분리는 현장 방법과 절차를 확인한 뒤 확정한다.
4. **시작조건을 관찰 가능한 상태로 바꾼다.** ‘준비 완료’라고 쓰지 않고 적용 도면 식별 가능, 선행 작업면 인계, 해당 자재의 작업면 사용 가능, 접근·장비 조건 확보, 프로젝트에서 요구하는 작업 전 안전조치 완료처럼 현장에서 예·아니오로 답할 수 있게 쓴다.
5. **완료조건과 증빙을 같이 쓴다.** 정의된 구간의 조립 완료, 자체점검에서 발견된 미완료 사항 해소, 검사 요청에 필요한 기록 준비를 적는다. 도면 식별정보가 있는 점검기록, 위치가 구별되는 사진, 작업일보 등 어떤 자료로 상태를 입증할지도 연결한다.
6. **검사 상태를 분리할지 판단한다.** 검사 대기시간과 시공 완료시간을 따로 봐야 하거나 담당 역할·증빙·후속 착수조건이 다르면 별도 Activity 또는 별도 일정 통제로 관리할 후보가 된다. 반대로 기간 영향 없이 단순 기록만 늘리는 분할이라면 Activity가 아니라 체크리스트가 적절할 수 있다.
7. **상태 갱신 담당과 승인 역할을 구분한다.** 공사담당자가 현장 상태를 갱신한다고 해서 품질 합격이나 설계 변경을 승인할 권한이 생기는 것은 아니다. 실제 권한은 프로젝트 책임체계에서 확인한다.
8. **후속 작업 인계 대상을 적는다.** ‘완료’만 쓰지 않고 누가 어떤 상태와 자료를 받아야 후속 작업을 시작할 수 있는지 기록한다.
9. **현장 판정 시험을 한다.** 공사담당자, 작업조 책임자, 품질담당자에게 같은 정의를 보여 주고 미착수·진행·완료를 각각 판정하게 한다. 답이 다르면 Activity 정의가 아직 모호한 것이다.

## Activity 정의서 작성 예시

| 항목 | 교육용 작성 예 |
|---|---|
| 명칭 | B2 교육구간 α 바닥부 철근 조립 및 자체점검 |
| 위치·대상 | WBS 사전과 적용 도면에서 특정한 교육구간 α의 바닥부 철근 범위 |
| 포함 | 해당 범위의 조립, 위치·누락에 대한 자체점검, 검사 요청 준비자료 작성 |
| 제외 | 자재 구매·운송, 다른 공종 매립물 설치, 프로젝트 절차상 공식 검사·승인, 검사 후 별도 보완작업 |
| 시작조건 | 적용 도면 식별, 선행 작업면 인계, 자재 사용 가능 상태, 접근·장비 조건, 요구되는 작업 전 안전조치 확보 |
| 완료조건 | 정의된 범위의 조립과 자체점검 완료, 확인된 미완료 사항 해소, 필요한 증빙 준비 |
| 상태 갱신 담당 | 해당 구간 공사담당 역할. 실제 조직의 담당자는 책임체계에서 지정 |
| 증빙 | 도면 식별정보가 연결된 자체점검 기록, 위치 식별 사진, 작업일보 |
| 후속 인계 | 프로젝트 절차에서 정한 검사·확인 단계에 자료와 작업면을 인계 |

공식 검사 결과가 후속 공종의 필수 착수조건이라면 위 시공 Activity의 완료만으로 후속 작업을 풀어서는 안 된다. 별도 검사 Activity 또는 마일스톤으로 둘지는 검사 절차, 예상 소요, 상태 갱신 필요성을 확인한 뒤 결정한다.

## 관계자와 정보교환 예시

- **계획담당자 → 공사담당자:** “교육구간 α에서 철근 조립 완료와 다음 단계 인계 사이에 별도 현장 조치가 있습니까? 작업면을 넘길 수 있는 상태를 적용 도면과 자체점검 기록으로 설명해 주십시오.”
- **계획담당자 → 품질담당자:** “이 공종의 확인 시점, 요청 문서명, 다음 단계 진행 조건과 결과 기록은 어느 프로젝트 문서에 있습니까? 일정 확정 전까지 근거 문서의 해당 항목을 회신해 주십시오.”
- **계획담당자 → 조달담당자:** “반입 예정이 아니라 교육구간 α에서 사용할 수 있는 상태가 되는 시점과 이를 확인할 자료가 무엇입니까?”
- **계획담당자 → 안전담당자:** “이 작업의 착수 전에 필요한 현장 통제 중 일정에 반영해야 할 조건은 무엇이며, 완료 여부는 어떤 기록으로 확인합니까?”

회신시한은 상세공정 확정 전으로 정한다. 품질 절차의 근거가 그때까지 확인되지 않으면 검사 상태의 분리 여부는 확정하지 않고 미결사항으로 남긴다.

## 핵심 숫자와 해석

교육 예시의 최초 WBS 말단 후보는 **1건**이지만, 그 안에는 시공·매립물·거푸집·검사라는 **4종의 상태 변화**가 섞여 있다. 그렇다고 자동으로 Activity 4건을 만드는 것은 아니다. 담당 역할, 시작·완료조건, 증빙, 후속 인계와 일정 영향이 독립적인지를 보고 분할한다.

진도율 **100%**는 ‘현장에서 대체로 끝나 보임’이 아니라 그 Activity에 기록한 완료조건을 모두 만족했다는 뜻이어야 한다. 검사 요청서를 제출했다는 사실은 검사 완료나 후속 작업 착수 허용과 같지 않다. 진도 가중치와 기성 인정 기준은 프로젝트별 기준을 확인하며, 이 예시의 상태 종류를 정상 판정 기준이나 생산성 기준으로 사용하지 않는다.

## 정상상태와 이상징후

**정상상태**는 서로 다른 담당자가 같은 적용 개정과 위치를 찾고, 동일한 시작·완료 판정을 내리며, 완료 증빙과 후속 인계 대상을 설명할 수 있는 상태다. 자재 반입, 시공 완료, 검사 요청, 검사 결과가 서로 다른 상태로 기록되어야 한다.

**이상징후**는 다음과 같다.

- 명칭이 ‘B2 작업’, ‘구조물 준비’, ‘검측 포함’처럼 위치·대상·행동을 보여 주지 않는다.
- 한 Activity 안에서 작업조, 작업면, 완료 증빙과 진도 기준이 여러 번 바뀐다.
- 시작조건이 ‘자재 발주 완료’, 완료조건이 ‘작업 완료’처럼 현장 관찰로 판정할 수 없다.
- 도면번호는 있으나 개정과 적용 상태가 없다.
- 검사 요청만 하고 완료 처리하거나, 미완료·부적합 사항이 남았는데 후속 작업에 인계한다.
- 너무 잘게 나누어 상태 갱신보다 행정 입력이 많아지고 실제 인계점이 보이지 않는다.

## 초보자가 반드시 해야 할 질문

- 이 Activity의 정확한 위치와 제외 경계는 어디인가?
- 어떤 도면번호·개정·사용 상태를 기준으로 하는가?
- 시작 직전에 현장에서 눈으로 확인할 조건은 무엇인가?
- ‘완료’라고 말할 때 실제 상태와 증빙은 무엇인가?
- 자재 반입, 시공, 자체점검, 공식 검사 중 무엇이 이 Activity에 포함되는가?
- 누가 상태를 갱신하고, 누가 검사·승인 또는 다음 단계 진행을 판단하는가?
- 완료 후 어느 공종·담당자에게 무엇을 넘기는가?
- 도면 변경이나 검사 결과 미충족 시 기존 완료 상태를 다시 열어야 하는가?

## 잘못 판단한 결과

Activity가 지나치게 크면 일부 작업 지연이 전체 진도 속에 숨고, 현장에서는 끝나지 않았는데 공정표만 완료될 수 있다. 반대로 지나치게 작으면 실질적인 인계 없이 기록만 늘어나 작업일보·검측·기성 범위가 서로 달라진다. 시공과 검사를 한 항목에 무조건 묶으면 시공 완료와 검사 대기를 구분하지 못하고, 무조건 분리하면 실제 일정 영향이 없는 문서행위를 과도하게 관리할 수 있다. 그 결과 후속 공종의 조기 착수, 진도 과대계상, 물량 중복, 검사 누락, 변경 영향 추적 실패가 발생한다.

## 지금의 결정·보류와 후속공정 인계

현재는 ‘교육구간 α 바닥부 철근 조립 및 자체점검’을 시공 Activity 후보로 정의한다. 공식 검사 상태는 **보류**한다. 품질담당 역할은 프로젝트 품질계획에서 검사 시점·문서명·다음 단계 진행조건을 찾아 상세공정 확정 전 회신한다. 계획담당자는 회신을 받아 별도 Activity, 마일스톤 또는 완료조건 중 어떤 방식이 상태를 가장 명확히 보여 주는지 결정한다.

시공 Activity 완료 직후에는 증빙을 검사·확인 담당 역할에 인계한다. 후속 작업은 프로젝트 절차에서 요구하는 확인 상태가 확보되기 전에 자동 착수시키지 않는다. 첫 재확인은 현장 최초 착수 직전 시작조건 점검 때, 두 번째는 시공 완료 보고와 증빙 제출 때, 세 번째는 후속 작업이 실제 작업면을 인수하기 직전에 한다. 도면 개정, 작업구간 변경, 담당 작업조 변경 또는 검사 절차 변경이 발생하면 정기 갱신 시점까지 기다리지 않고 Activity 정의를 다시 연다.

이 재확인의 목적은 문서가 배포됐는지 확인하는 데 있지 않다. 현장 담당자들이 같은 정의로 미착수·진행·완료를 판정하고, 후속 담당자가 같은 위치·개정·증빙으로 작업면을 인수하는지를 확인하는 데 있다.
