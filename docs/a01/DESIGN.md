# A01 신규 구조안과 저장소 분석

2026-09-24. 기존 정적 웹은 `docs/curriculum.json`의 18개 소설/학습 쌍을 `tools/build-book.js`로 `data/book.js`에 묶는다. 기존 `docs/field`는 미추적 작업 중 초안이며 A01 한 문서에 Level 1~4가 혼합되어 있다. 해당 초안과 기존 소설·CASE를 보존하고 새 교과과정은 `docs/a01`에 둔다.

기존 집필 규칙의 자료·이유·결정·후속 영향, 회사 절차 창작 금지, 교육용 수치 고지를 계승한다. 기존 소설/PART B 10절 형식은 새 Layer 1의 형식으로 강제하지 않는다. CASE 14의 CP·Float·공유자원 원리는 연결 자료이며 기존 수치를 신규 B2 사례의 실적으로 혼합하지 않는다.

Layer 1은 9개 파일: 담당자 업무 → 작업구간/WBS → Activity → 물량/Crew/생산성/Duration → 선후관계 → Constraint → 계획 계층 → 관계부서 조정 → 실적 갱신/재계획. 각 파일은 3,000~6,000자 목표이며 Level 2에 집중한다. 공통 배경은 가상 도심 지하차도 B2 BOX다. 각 계산 예시는 시점과 가정을 명시한다.

Layer 2는 승인 지연·생산성·크레인·작업면·납기·검측·증원·물량 변경의 8개 단위문제다. Layer 3은 금요일 타설 가능 여부를 묻는 통합 CASE 1개다. Layer 1 전체 PASS 이후에만 문제를 생성한다.

API Curriculum Architect가 챕터별 목적·선수지식·개념·실제 행동·후속문제·직무 연결을 구조화한다. Writer가 본문을 작성한다. Field/Pedagogy/Quantitative Reviewer의 독립 점수와 차단 사유를 모두 만족해야 한다. 산술은 제한된 식 해석기로 독립 검증한다. 날짜·달력·자원·Float·비용 범위의 의미 일치는 Analyst가 대조한다. Chief Editor 이후 동일 검수를 다시 수행한다. 총 재작성 최대 3회 뒤에도 실패하면 needs_manual_review로 보존하며 본문 목차에는 반영하지 않는다.

기본 모델은 gpt-5.6-sol이다. API 요청/프롬프트/모델/컨텍스트 해시로 응답을 재사용하고 PASS 상태와 실제 발행 파일 해시를 확인한다. API key는 환경에서만 읽고 감사기록에 저장하지 않는다. 기존 웹의 소설/학습 경로는 변경하지 않으며 신규 교재는 Markdown 목차로 제공한다.
