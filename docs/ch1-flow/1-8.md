# 1-8. 하나가 바뀌면 어디까지 번지는가

## 이 절이 답하는 질문

> **한 곳에서 생긴 변화가 왜 다른 관리업무까지 흔드는가. 어디까지 확인해야 다 본 것인가.**

앞의 절들은 Flow를 하나씩 봤다. 이 절은 **Flow들 사이의 연결**을 본다. 현장에서 일어나는 실수의 상당수는 하나의 Flow 안에서 틀려서가 아니라, **다른 Flow로 번지는 것을 놓쳐서** 생긴다.

---

## 왜 번지는가

1-0에서 본 것을 다시 꺼낸다.

> **대상은 하나인데 재는 자가 여럿이다.**

같은 벽체 하나를 공정은 시간으로, 자원은 사람·장비·자재로, 원가는 돈으로, 품질은 요구조건으로 잰다. 그 벽체가 바뀌면 **네 개의 자가 전부 다른 값을 가리키게 된다.** 하나만 고치고 나머지를 두면, 네 개의 장부가 서로 맞지 않는 상태가 된다.

그래서 변화가 생기면 묻는 질문은 언제나 같다.

> **"이것이 나머지 자들에는 어떻게 보이는가?"**

---

## 전파 경로 1 — 설계변경

가장 넓게 번지는 경우다.

```text
                    설계변경
                       ↓
                    물량 변경
                       ↓
   ┌───────────┬───────┴───────┬───────────┐
   ↓           ↓               ↓           ↓
 공정 변경    자원 변경        원가 변경    품질·검측 변경
   │           │               │           │
   ↓           ↓               ↓           ↓
 Duration    Crew 재산정      직접비       검사 항목
 Logic       장비 재배차      간접비       시험 빈도
 CP 재계산   자재 재발주      EAC          Hold Point 위치
 Milestone                   계약 처리
```

### 각 경로에서 실제로 해야 하는 것

**공정** — 물량이 바뀌었으니 Duration을 다시 산정한다(1-2 ⑤). 작업이 추가되거나 없어지면 Activity와 선후관계가 바뀐다(③④). 그 결과 **CP가 바뀔 수 있다.** 전에는 여유가 있던 경로가 새 CP가 되는 일이 흔하다.

**자원** — 물량이 늘면 필요 Crew가 는다(1-3 ③). 자재를 다시 발주해야 하면 **제작·운송 기간이 새로 필요하다**(③의 자재 칸). 이것이 공정에 다시 영향을 준다.

**원가** — 직접비가 바뀐다. 기간이 늘면 간접비가 시간만큼 는다(1-4 ①). EAC를 다시 계산한다(⑥).

**품질·검측** — 새로운 공종이나 자재가 들어오면 **검사 항목과 시험이 달라진다**(1-7). 검사·시험계획을 고쳐야 한다. Hold Point의 위치가 바뀔 수도 있다.

### 가장 자주 빠지는 것

**품질·검측 경로**다. 도면을 고치고 공정표를 고치고 예산을 고치는 것까지는 하는데, 검사·시험계획을 고치는 것을 잊는다. 그러면 새로 들어온 것에 대해 무엇을 확인해야 하는지 정해지지 않은 채 시공된다.

## 전파 경로 2 — 지연

```text
              한 작업이 늦어졌다
                     ↓
              CP 위인가? (1-2 ⑪)
                     ↓
        ┌────────────┴────────────┐
      아니다                      그렇다
        │                          │
   Float가 줄어든다          후속 전체가 밀린다
        │                          │
   (언젠가 CP가 될 수 있다)          ↓
                    ┌──────────────┼──────────────┐
                    ↓              ↓              ↓
              자원이 묶인다     간접비 증가     Milestone 위험
                    │              │              │
                    ↓              ↓              ↓
            다른 작업에 못 감   EAC 증가      계약적 문제 (1-10)
```

### 지연이 자원으로 번지는 방식

이것이 잘 안 보인다. 한 작업이 늦으면 **그 작업에 묶인 자원이 다음 작업으로 못 간다.** 그러면 지연이 없었던 다른 작업까지 늦어진다.

```text
   A작업 3일 지연
     → A에 있던 Crew가 3일 늦게 빠짐
       → B작업 착수가 3일 늦어짐
         → B는 CP 위였다
           → 준공일 3일 지연
```

A는 Float가 있어서 괜찮다고 판단했는데, 자원을 통해 CP 위의 B로 옮겨간 경우다. **Float만 보고 자원 연결을 안 보면 이 경로를 놓친다.**

---

## 전파 경로 3 — 자원 부족

```text
        필요 자원 > 가용 자원 (1-3 ④)
                    ↓
        ┌───────────┼───────────┐
        ↓           ↓           ↓
   자원을 늘린다  기간을 늘린다  작업을 나눈다
        ↓           ↓           ↓
    원가 증가    공정 지연    작업면·인계 경계 변경
                     ↓              ↓
                간접비 증가     검측 단위 변경
```

세 가지 대응 중 **어느 것도 자원 안에서 끝나지 않는다.** 이것이 자원 문제를 자원 담당자 혼자 결정할 수 없는 이유다.

---

## 전파 경로 4 — 품질 문제

```text
         불합격 또는 부적합 발견
                   ↓
            1-5 문제처리 Flow
                   ↓
   ┌───────────┬───┴────┬───────────┐
   ↓           ↓        ↓           ↓
 재시공      원인 조사   후속 중단   횡전개 점검
   ↓           ↓        ↓           ↓
 원가 증가   기술질의   공정 지연   다른 위치 재점검
             (1-6)                    ↓
               ↓                  추가 공정·원가
           설계변경 가능성
               ↓
           경로 1로 합류
```

품질 문제는 **경로가 길다.** 그 자리에서 끝나지 않고, 같은 조건의 다른 위치까지 번진다(1-5 ⑮).

---

## 역방향 전파

전파는 위에서 아래로만 가지 않는다. **아래에서 위로 올라오는 경우**도 있다.

| 출발 | 도착 |
|---|---|
| 원가가 초과됐다 | → 더 싼 공법을 검토한다 → **설계변경**이 필요할 수 있다 |
| 자재를 못 구한다 | → 대체 자재를 쓴다 → **승인**이 필요하다 → 품질 기준이 바뀐다 |
| 인력이 없다 | → 공법을 바꾼다 → **설계·시공계획 변경** |
| 공기가 부족하다 | → 병행 시공 → **간섭 검토, 안전계획 변경** |

그래서 "설계 → 시공"이라는 일방향만 생각하면 안 된다. **현실의 제약이 설계를 되돌려 바꾸기도 한다.**

---

## 놓치기 쉬운 경로

앞의 그림들에 잘 안 나오지만 실제로는 자주 문제가 되는 것들이다.

| 경로 | 무엇이 문제인가 |
|---|---|
| **안전계획** | 공법이나 순서가 바뀌면 위험요인이 바뀐다. 작업허가 조건도 바뀐다 |
| **인접 공종** | 내 변경이 옆 공종의 작업면·동선·간섭을 바꾼다 |
| **인허가 · 외부기관** | 점용, 굴착, 교통처리 조건이 바뀌면 재협의가 필요하고 시간이 길다 |
| **민원 · 주변 영향** | 작업 시간대, 소음, 진동 조건 |
| **기성 · 계약** | 물량과 범위가 바뀌면 기성 산정 기준이 바뀐다 (1-10) |
| **협력업체 계약** | 범위·물량·기간이 바뀌면 하도급 계약도 조정 대상이다 |

특히 **외부기관이 관련된 경로는 시간이 길다.** 내부에서 아무리 빨리 결정해도 외부 절차가 끝나야 움직인다. 전파 경로 중 이것이 있으면 그것이 곧 CP가 된다.

---

## 전파를 추적하는 방법

변화가 생겼을 때 다음을 순서대로 묻는다. **하나씩 다 묻는 것이 요령이다.** 기억에 의존하면 반드시 빠뜨린다.

```text
① 무엇이 바뀌었는가          — 범위, 물량, 방법, 조건, 일정 중 무엇인가
② 물량이 바뀌었는가          — 예 → 공정·자원·원가 전부
③ 작업이 추가·삭제됐는가      — 예 → Activity와 선후관계
④ 기간이 바뀌었는가          — 예 → CP 재계산, 간접비
⑤ 자원이 바뀌었는가          — 예 → 투입계획, 배차, 발주
⑥ 자재가 바뀌었는가          — 예 → 승인, 납기, 검사 항목
⑦ 방법이 바뀌었는가          — 예 → 시공계획서, 안전계획, 검사·시험계획
⑧ 검사할 것이 바뀌었는가      — 예 → 검사·시험계획, Hold Point
⑨ 인접 공종에 영향이 있는가   — 예 → 해당 담당자와 협의
⑩ 외부기관·인허가가 걸리는가  — 예 → 소요 기간부터 확인
⑪ 계약 범위·금액·기간에 닿는가 — 예 → 1-10 계약 절차
⑫ 누구에게 알려야 하는가      — 빠진 사람이 없는가
```

### 문서 기준으로 다시 확인하기

위 질문의 답을 **고쳐야 할 문서 목록**으로 바꿔 본다.

| 문서 | 고쳤는가 |
|---|---|
| 시공상세도 | |
| 시공계획서 | |
| 공정표 (Baseline / 현행) | |
| 실행예산 | |
| 투입계획 · 배차계획 | |
| 자재 발주 · 납기계획 | |
| 검사 · 시험계획 | |
| 안전계획 · 작업허가 | |
| 협력업체 계약 | |

**기술 문서만 고치고 관리 문서를 안 고치는 것**이 가장 흔한 누락이다. 도면은 바뀌었는데 공정표와 예산이 그대로면, 나중에 왜 늦고 왜 더 들었는지 설명할 근거가 사라진다.

---

## 시간 감각

전파 경로마다 **걸리는 시간이 다르다.** 이것을 모르면 조치 순서를 잘못 잡는다.

| 경로 | 대략의 무게 |
|---|---|
| 공정표 갱신 | 짧다 |
| 투입계획 조정 | 짧다 |
| 시공상세 수정 + 승인 | 중간. 승인 대기가 변수다 |
| 자재 재발주 | 길다. 제작품이면 매우 길다 |
| 설계변경 절차 | 길다 |
| 외부기관 재협의 | 가장 길다 |

그래서 변화가 생기면 **가장 긴 경로부터 착수한다.** 짧은 것을 먼저 처리하고 나중에 긴 것을 시작하면, 그 시간이 전부 지연으로 남는다.

---

## 자주 혼동하는 개념

| | | 차이 |
|---|---|---|
| 기술적 조치 완료 | 변경 반영 완료 | 후자는 관리 문서까지 포함한다 |
| 공정 영향 | 자원 영향 | 자원을 통해 다른 작업으로 번지는 경로가 따로 있다 |
| Float가 있다 | 영향이 없다 | 자원 연결로 CP에 닿을 수 있다 |
| 변경 통보 | 변경 반영 | 알린 것과 상대가 계획을 고친 것은 다르다 |
| 내부 절차 | 외부 절차 | 후자는 시간을 통제할 수 없고 대개 길다 |

---

## 잘못 이해하면 생기는 일

**물량만 고치고 공정을 안 고치면** — 늘어난 물량을 원래 기간에 하는 계획이 남는다. 당연히 못 지킨다.

**공정만 고치고 원가를 안 고치면** — 기간이 늘었는데 간접비 증가가 전망에 안 들어간다. EAC가 실제보다 작게 나온다.

**검사·시험계획을 안 고치면** — 새로 들어온 것에 대해 무엇을 확인할지 정해지지 않은 채 시공된다.

**안전계획을 안 고치면** — 방법이 바뀌었는데 위험요인 검토가 이전 방법 기준으로 남는다.

**Float만 보고 자원 연결을 안 보면** — 여유 있는 작업의 지연이 CP 위의 작업으로 옮겨가는 것을 놓친다.

**긴 경로를 나중에 시작하면** — 자재 재발주나 외부 협의가 전체를 결정하는데, 그것을 마지막에 시작해서 그만큼 다 밀린다.

**전파 점검을 기억에 의존하면** — 매번 다른 것을 빠뜨린다. 목록으로 확인해야 한다.

---

## 스스로 확인

1. 하나의 변화가 여러 Flow로 번지는 근본 이유는 무엇인가.
2. 설계변경이 끌고 오는 네 갈래를 말하고, 그중 가장 자주 빠지는 것은 무엇인지 말해 보라.
3. Float가 있는 작업의 지연이 준공일에 영향을 주는 경로를 설명해 보라.
4. 자원 부족에 대응하는 세 가지 방법과 각각이 어디로 번지는지 말해 보라.
5. 아래에서 위로 올라가는 전파의 예를 두 가지 들어 보라.
6. 놓치기 쉬운 경로 여섯 가지 중 네 개를 들어 보라.
7. 변화가 생겼을 때 왜 가장 긴 경로부터 착수해야 하는가.
8. 고쳐야 할 문서 아홉 가지 중 여섯 개를 들어 보라.
