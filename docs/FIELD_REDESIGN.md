# 실무형 튜터 구조 분석과 확장 설계

2026-09-24. 로컬 origin이 요청 저장소와 일치함을 확인했다. 변경 전 작업 트리는 깨끗했다. README, 두 AUTHORING_GUIDE, REBUILD_DESIGN, curriculum, PART A/B 전 장의 구조, 카드·CASE 분류, 공정·원가·통합 CASE 14·16·17, 앱과 빌드·검증 코드를 분석했다.

## Phase 1 — 유지할 구조와 부족한 지식

| 현재 구성 | 강점 | 부족한 점과 처리 |
|---|---|---|
| PART A 18장 | 관찰→작업 이해→구간 연결→문제 판단→직무 연결→통합 판단 | 현장 경험의 입구로 유지 |
| PART B 18장, 10개 절 | 미확정 정보·시간축·조건변경·공사/공무 연결 | 업무별 Input/Output·담당 숫자·정상상태가 분산됨. 독립 업무 본문을 연결 |
| CASE 14 | CP·Float·병렬 경로·Recovery | Baseline/Data Date/Actual/잔여기간 비교 및 공유 자원 계산 추가 |
| CASE 16 | 완료량 대응 예산·발생원가·EAC·회피비 | Commitment 잔액·현금·기성·가속 경제성의 비교 실습 추가 |

| 기본 82·도메인 108 카드 | 용어와 기술 회상 | 업무 지식 본체로 사용하지 않음 |
| 보조 CASE 32개 | 대안표·답변 저장·자기평가 | 면접형 종합 답변과 반복 틀이 많음. 새 숫자 CASE로 진입 링크를 제공하고 기존 답변은 보존 |
| 웹·빌드 | 서버 없는 실행·로컬 기록·소설/학습 분리 | 업무·문제은행도 원문에서 빌드하고 웹 경로로 연결 |

중복은 공정/원가의 용어 설명과 CASE별 공통 대안 표현에 집중되어 있다. 동일 본문을 18장에 복사하지 않는다. 기간·발생원가의 정의는 업무 본문에 두고 사례에서는 적용 조건을 바꾼다. 기존 PART B의 공정·원가·품질 원리는 유지한다.

누락 또는 파편적으로만 다룬 업무는 조직·인원·자금계획, 외주/자재 계약 역산, 투입예정원가, 실정보고, 공법개발, 계획서와 시공성의 구별, 작업구획·시공순서, 장비배차·자재재고, 파트너사 실적, 하자 분석·처리·재발방지·민원·고객·준공 후 추적이다. 요청 목록의 A 8, B 7, C 9, D 9, E 6 = 39개를 별도 문서로 관리한다.

## Phase 2 — 정보구조

`수행업무 본문(Level 1~2) → 해당 문서의 미니 판단문제(Level 3) → 통합 CASE(Level 4) → 조건변경 후 재판단`을 기본 경로로 한다. PART A는 상황 입구, PART B는 기존 사건 해부로 남긴다. 본문과 문제은행은 어느 쪽에서 시작해도 왕복할 수 있다.

- `docs/field/tasks/ID.md`: 39개 업무, 요청된 14절. 계획/시공 중 품질과 계획/당일 인원을 각각 구분한다.
- `docs/field/cases/ID.md`: 숫자·미확정·질문·추가 정보·6단계 해설·조건변경·평가.
- `docs/field/curriculum.json`: 업무/CASE/기존 장/보조 CASE 연결의 단일 대장.
- `docs/field/README.md`: 전체 업무와 통합 CASE 목차.
- `data/field.js`: 원문에서 생성. 런타임 네트워크 없이 웹에서 읽는다.
- 웹 `#field`, `#field/task/ID`, `#field/case/ID`: 업무→미니문제→CASE 이동, 답변 저장, 추가정보·해설 접기.

수치·생산성·계약/검사 시한은 모두 교육용 가정이다. 작업일·시각·비용 범위·단위를 밝힌다. 실제 법령·설계 허용치나 계약 권리를 임의로 정하지 않는다. 공정망 계산은 기술 승인이나 실제 공법 선정의 대체물이 아니다.

## Phase 3 — 대표 샘플의 출고 기준

인력 C06, 공정 A01/A05, 원가 B01을 먼저 집필한다. 네 문서에서 실제 자료, 정상/이상, 질문 순서, 숫자 계산, 대안과 타 구간 영향, 담당/결정시한, 재확인이 읽혀야 한다. 각 14절과 Level 1~4 연결을 확인한 후 나머지 업무를 확장한다. 인원을 생산성에 단순 비례시키거나 지급액으로 EAC를 계산하는 답은 통과시키지 않는다.

## Phase 4·5 — 확장과 문제은행

39개 업무별로 고유 자료·관리숫자·실행 절차·계산/판단 문제를 쓴다. 통합 CASE는 인력 전환, 자원 제약 공정, 원가, 계약/납기, 도면 변경, 인수/검측, 준공 후 하자, 자금/파트너사로 구성한다. 각 CASE는 복수 업무를 되불러 사용하고 기존 CASE 14/16/17/18 및 보조 문제로 이어진다.

웹에서는 최초 질문에 답을 적은 뒤 추가정보를 열고, 해설을 별도로 열어 비교한다. 질문 생성→자료/출처→수치/가정→대안 영향→담당/시한→재확인의 근거를 사람이 평가한다. 키워드 수로 자동 채점하지 않는다. 읽음과 답변은 개정판별로 관리하며 기존 카드·보조 CASE 기록을 보존한다.

## 검증 범위

39개 업무/14절/미니문제/상호 링크와 원문-웹 일치, 계산 예시의 단위·조건 및 결과, CASE의 정보 공개 구조를 검사한다. 브라우저에서는 직접 파일 실행·모바일 표·답변 저장/복원·기존 기록 보존·해설 접기·왕복 경로·기존 기능을 확인한다. 구조 검사는 실제 현장 기술 감수나 교육 효과 검증을 대신하지 않는다.
