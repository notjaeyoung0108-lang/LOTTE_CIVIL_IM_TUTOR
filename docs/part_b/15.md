# CASE 15. 지시를 계약의 언어로

## PART B. 학습

### 1. 문제상황

기존 관로와 계획 접속 상세가 충돌했다. 회의에서 현장 조정 발언이 있었으나 변경 상세·승인 범위·비용·기간은 확정되지 않았다. 협력업체는 추가공사와 장비 투입 여부를 묻는다.

### 2. 아직 판단할 수 없는 것

원계약 도면·시방·내역과 적용 관계, 실제 관로 조사, 발언자의 권한, 기술 검토·계약 변경 절차, 통지 수신자·기한이 필요하다. 구두 발언의 효과는 계약별 검토 대상이며 무조건 무효나 지급 확정으로 단정하지 않는다.

### 3. 공사담당자의 사고체계

| 행동 | 왜 | 하지 않으면 | 후속 영향 |
|---|---|---|---|
| 영향부 임의 시공·은폐 보류, 필요한 보호 조치 | 잘못된 접속이 기능과 주변 시설에 영향 | 되돌리기 어려운 시공 | 원상태·실측·안전 조건 보존 |
| 변경 전후 위치·물량·대안을 기술질의 | 모호한 질문은 실행 상세를 못 줌 | 회신 반복·납기 지연 | 설계 검토·승인 범위 특정 |
| 승인 상세를 도면·작업계획·검사에 반영 | 회의 발언만 작업자에게 전하면 오해 | 구도면 시공 재발 | 배포·실행·인수 확인 |
| 무관한 기존 승인 작업의 독립성 확인 | 변경 협의 중 가능한 작업이 있음 | 불필요한 전체 대기 | 현장 운영과 기록 지속 |

### 4. 공무담당자의 사고체계

| 행동 | 왜 | 하지 않으면 | 후속 영향 |
|---|---|---|---|
| 지시 주체·원인·범위·계약 의무 확인 | 기술 필요와 계약 지급은 다른 질문 | 비용 권리 성급 확정 | 적절한 통지·승인 경로 선택 |
| 접수·통지·회의록과 미결 항목 추적 | 나중에 필요한 시점 증빙 확보 | 절차 누락·오해 | 계약에 따른 변경 협의 |
| 물량·단가·재작업·공기 영향을 분리 제출 | 복수 원인이 겹치고 물량도 잠정 | 중복·불명확 청구 | 확정·미합의 금액 관리 |
| 실행 결과를 기성·정산까지 연결 | 승인 예정량과 실제량은 달라질 수 있음 | 변경 대장과 실물 불일치 | 최종 수량·기간·증빙 종결 |

### 5. 공사 ↔ 공무 연결

공사는 원상태 사진, 변경 전후 수량, 소요일, 투입 및 대기 원인을 제공한다. 공무는 기술질의와 별도로 필요한 계약 통지를 준비하고 '이 대기는 작업로 차단과 겹치는가'를 되묻는다. 안전상 필요한 긴급 보호를 금액 미합의 때문에 늦추지 않고 해당 절차에 따라 사실·지시·통지를 남긴다.

### 6. 기술원리와 공간

```text
현장 불일치 → 실측·위치·대안 ─→ RFI → 기술 검토·승인 상세
          └→ 원인·지시·계약 ─→ 통지 → 금액·공기 변경 협의
두 경로의 결과 → 배포·시공·검사 → 기성·준공·정산
```

도급은 약정한 공사를 수행하고 대가를 받는 계약 관계다. 설계변경은 기술·계약 절차와 연결되며 추가공사는 기존 계약범위와 비교해 판단한다. 감리·설계사·발주처·현장소장의 권한은 사업별 전결과 계약 경로로 특정한다. RFI 답변이 비용·기간 승인까지 포함하는지는 해당 문서와 권한을 확인해야 한다.

### 7. 시간축

지금 원상태와 발언을 기록하고 2시간 뒤 질의·통지 필요를 나눈다. 오늘 종료 전 회신 및 발주 결정시한을 정한다. 내일 승인 범위로 작업을 계획하고 일주일 뒤 실제 변경량을 갱신한다. 정산에는 기술 상세와 금액·기간 합의가 따로 추적돼야 한다.

### 8. 현장용어

공문은 정해진 상대방에게 의사를 전달하는 문서이며 제목보다 내용·수신·기한·권한이 중요하다. 회의록은 참석자·발언·결정·미결·담당·기한을 구분한다. 귀책은 사실관계와 계약 의무를 검토한 결과다.

### 9. 조건 변경 시뮬레이션

승인된 기술 상세만 도착하면 시공 준비와 별도로 금액·기간 협의를 추적한다. 작업이 이미 진행됐다면 실행 범위·지시·원상태 자료를 추가 확보하며 사후 승인을 당연시하지 않는다. 원계약에 포함된 업무라면 추가 물량이 있어도 지급 산정 방식에 따라 결과가 달라진다. 공공·민간·하도급 계약을 한 절차로 묶지 않는다.

### 10. 판단 연습과 핵심원칙

“현장에 맞게 하세요”를 결정 가능한 질의로 바꾸라.

**해설:** 위치·불일치 치수·적용 문서·기능 영향·대안·회신 필요일과 요청하는 승인 범위를 쓴다. 변경의 기술적 필요, 실행 권한, 대가·기간을 각 근거로 연결한다.
