# 현장 시뮬레이션 교재 집필 규칙

기준: d51e7e3의 기술 골격과 10개 장·파일명·학습 링크를 유지한다. 목표는 현장 5년차가 고려하는 판단 프레임이며, 설명은 신입이 이유를 따라갈 수 있게 쓴다. 교재 수료를 실제 경력이나 승인 자격으로 표현하지 않는다.

## 등장인물과 시간

- **안재영:** 모든 장의 주인공. 1장 신입, 2장 1년차, 3~4장 2년차, 5~6장 3년차, 7~8장 4년차, 9~10장 5년차.
- **김도윤:** 초기 장면에서 5년차 선배로 등장한다. 후반에서도 계속 5년차라고 고정하지 않는다.
- **박성호:** 초기 철근 작업을 함께한 협력업체 반장. 담당 밖 설계·승인 판단을 대신하지 않는다.
- **이수진:** 공무 담당. 기술 회신과 계약상 금액·기간 판단을 구분하도록 돕는다.

다년간의 가상 현장 기록이다. 다른 구조물·현장은 BOX-02, BOX-03, A/B/C처럼 위치를 구분한다. 7장의 도로·교량·터널 장면은 서로 다른 날이다. 연차·호칭을 승인 권한의 근거로 쓰지 않는다.

## 장면에서 해설로

1. 시간·장소·사람·작업면·장비 위치를 보여준다. 위험 장면은 안전한 관찰·보고 위치를 분명히 한다.
2. 짧은 한국 현장 대화로 사건을 드러내고 ‘화면 정지’에서 독자가 먼저 판단하게 한다.
3. 신입의 자연스러운 오판을 보여주고, 무엇을 놓쳤는지 인과로 설명한다.
4. 행동마다 이유·전제·권한·증거를 연결한다. ‘확인한다’면 무엇으로 확인하며 결과에 따라 무엇이 달라지는지 쓴다.
5. 통제 범위와 계속 가능한 조건을 함께 쓴다. 불명확한 위험 영향은 보수적으로 보호하고 기술 검토로 좁힌다. 위험을 과소평가하기 위한 부분 중지를 제안하지 않는다.
6. 지금·2시간 뒤·오늘 종료·내일·일주일 뒤·준공/정산을 필요에 따라 연결한다. 발생 가능한 경로와 확정 결과를 구분한다.
7. 품질·안전·공정·원가·계약·문서·승인 중 사건과 관련된 관점을 담당자·결정 시한과 연결한다.
8. 조건을 하나씩 바꾸고 달라진 통제·검토·재개 조건을 해설한다. 마지막에는 암기 대신 의사결정과 그 이유를 요구한다.

1장을 기준 샘플로 삼되 매 장을 같은 목록으로 채우지 않는다. 2장은 생산 사이클, 5장은 하중 경로, 7장은 공종 인계, 9장은 기술·계약의 두 경로처럼 기술 원리에 맞는 구조를 쓴다. 기존 계산과 실무 양식은 해설부에 유지하며 중복된 짧은 사례는 확장 사례로 통합한다.

## 용어와 기술 정확성

중요 용어는 처음 등장하는 대화·장면에 짧은 뜻을 붙이고, 표에는 용어·영어·현장 표현·정확한 의미·해당 장면의 중요성을 적는다. 영어 약어는 장별 첫 등장 시 Full Name을 함께 쓴다. 구어인 먹·루베와 공식적인 위치 표시·m³를 구별한다. 문서 명칭과 승인·검사 절차가 사업별로 다름을 밝힌다.

판정 수치·통지기한·인양·지보·양생 방법을 근거 없이 만들지 않는다. 가상 계산의 숫자는 가정·단위·적용 범위와 함께 쓴다. 구조·지반 성능과 변경 상세는 담당 기술 검토·승인 체계로 연결한다. 사진, 정상 계측값 한 번, 검측 요청, 회신 수신을 각각 적합성·재개 승인과 혼동하지 않는다.

공식 자료는 개념 검토와 현장 적용 조항 확인을 구분한다. 해외 안내의 수치·권한·절차를 국내 현장 규칙으로 옮기지 않는다. 실제 시공 지침으로 확정하려면 적용 설계·시방·계약·현행 법규·책임자 검토가 필요하다.

## Markdown과 검증

기존 앱이 지원하는 제목·문단·인용·목록·표·HTTPS 링크를 쓴다. 공간·흐름 도식은 fenced text 코드 블록을 사용한다. HTML과 Mermaid 런타임은 사용하지 않는다. 도식은 개념도인지 실제 설계인지 표시하며, 정렬 자체에 의존하지 않고 앞뒤 문장으로 관계를 설명한다.

`node tools/build-book.js`로 원문을 data/book.js에 반영하고 `node tools/validate.js`로 동기화를 확인한다. 도식 표시 수정 시 모바일 내부 스크롤과 HTML 이스케이프를 확인한다. 수정 전 사용자 변경은 보존하고, 파일명과 기존 학습 링크를 유지한다.
